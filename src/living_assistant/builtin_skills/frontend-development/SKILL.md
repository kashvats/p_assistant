# Frontend development

## When to use
A task asks you to implement screens, components or client-side behaviour.

## Steps
1. Read the design/requirements and the existing frontend files first; follow their structure and style.
2. Build the smallest working version first, then add states: loading, empty, error.
3. Connect to the real backend contract when there is one; do not fake data unless asked for a prototype.
4. Check the result: open or run it if a tool allows it, and at least re-read the files you wrote for syntax errors.
5. Report the files you created or changed.

## Rules and checks
- Inputs have labels; buttons have text or an accessible name.
- No secrets or API keys in frontend code.
- Write files only inside the project workspace.
