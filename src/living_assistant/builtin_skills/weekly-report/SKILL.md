# Weekly report

## When to use
The user asks for a weekly report, status update, progress summary or stand-up summary.

## Steps
1. Collect the material: what the user pasted, files they point to, finished todos, or (for code) recent git history - only from places the user mentions.
2. Group the work by project or goal.
3. Write:
   - **Highlights** - the 2-4 most important results, with numbers where available.
   - **Progress by project** - for each: done, in progress, next.
   - **Blockers and risks** - what is stuck and what help is needed.
   - **Next week** - 3-6 concrete planned items.
4. Keep it to one screen. Use plain language a manager outside the team understands.

## Rules and checks
- Do not overstate: "started" is not "done". Keep the user's own status words.
- Flag anything you inferred rather than read as "(to confirm)".
