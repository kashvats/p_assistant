# Technical writing

## When to use
A project needs docs, a README, a handover note or a delivery report.

## Steps
1. Read the actual files and commands; document what exists, not what was planned.
2. README order: what it is (1-2 sentences), requirements, install, run, test, configuration, project layout, known limitations.
3. Use exact commands in code blocks and check that the paths and names match the code.
4. Keep it short; link to details instead of repeating them.

## Rules and checks
- Never document a feature that is not implemented.
- List known limitations honestly.
